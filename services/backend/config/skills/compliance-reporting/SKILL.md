# Compliance Assessment Reporting

This is not a pentest report. It is a selected-framework control-readiness
report.

Use only the framework template generated by `prepare_report_context` for the
current run. Framework templates are not part of this skill package.

Required structure:

- Scope and controls assessed, with every selected-framework control ID written explicitly
- Assessment/report date from the current report context or finalizer preflight; do not invent a historical date
- Verdict and reason, with limitations beside every pass verdict
- Evidence inspected
- Limitations, missing context, and open action requests
- Next action

Do not claim certification, audit completion, or compliance. Say exactly
what Null-AI tested and what evidence supports the current readiness verdict.

For PCI DSS reports, use only CDE-scoped readiness and supporting-evidence
language. State the declared CDE boundary and SAQ/profile context when present,
or state that they are missing/unconfirmed. Never claim PCI compliance,
certification, ASV scan/pass/attestation, QSA approval, ROC completion, SAQ
completion, AOC issuance, or acquiring-bank approval.

`run.digest.recommendation` for compliance must be an agent-executable
control/evidence-review objective, such as re-checking a stale control,
reviewing fulfilled evidence, mapping uploaded evidence, or recording missing
evidence/action requests. Customer-side work belongs in action requests or
`next_prerequisites`, not as a pentest-style next target.
