# NestJS Specialization Methodology

Use this skill for Nest module/controller routes, guards, pipes, interceptors, serializers, metadata decorators, platform adapters, GraphQL/microservice transports, and background queues.

## Preconditions and Fast Applicability

Require confirmed NestJS/source, deployed module/config revision, evaluator identities/objects, and a safe operation. Default cap is twenty requests/messages and one reversible evaluator mutation.

## Surface Discovery and Prioritization

Map modules/controllers, global/controller/route guards, custom decorators/metadata, pipes/DTO validation, interceptors/serialization, exception filters, Express/Fastify adapter, Swagger, GraphQL, WebSockets/microservices, queues, and config.

## Safe Test Ladder

1. Trace one handler through lifecycle order.
2. Compare global versus route guard behavior with evaluator roles.
3. Send one extra/protected DTO canary field.
4. Compare HTTP and one observed alternate transport handler.
5. Verify interceptor/serializer output fields.
6. Correlate one queued evaluator job.
7. Confirm deployed module/revision.

## Variation Matrix

| Axis | Variants |
|---|---|
| guard | global, controller, route |
| input | pipe/DTO normal, one canary |
| output | interceptor/serializer |
| adapter | deployed Express/Fastify |
| transport | HTTP, one observed GraphQL/RPC/socket |
| async | direct, observed queue |

## Proof Standard

Proof requires class-specific behavior tied to exact handler/lifecycle metadata and runtime. Decorator appearance, Swagger exposure, missing guard on source line, or framework version alone is not proof.

## False Positives and Benign Lookalikes

- global guards may be registered outside controllers;
- metadata inheritance can change route policy;
- pipes can transform rather than reject;
- serializers can filter response fields;
- adapter behavior differs safely;
- microservice guards use different execution context.

## Missing Prerequisites and Blocked Behavior

Return `blocked` without deployed module/config, evaluator roles/data, or safe transport/job. Never convert blocked or ambiguous work into a finding.

## Tool Selection and Fallback

Use HTTP/browser/RPC capture, Swagger parsing, and source reads. Isolated Nest tests may override guards/pipes only to confirm controls, not as production proof.

## Handoffs and Duplicate Prevention

Hand authorization/property/input/GraphQL/WebSocket/gRPC/resource primitives to owners. NestJS owns lifecycle/configuration context.

## Stop, Cleanup, and Data Minimization

Stop at one platform-specific proof, twenty messages, or lifecycle uncertainty. Remove evaluator objects/jobs.

Never perform destructive actions or modify production providers/guards.
